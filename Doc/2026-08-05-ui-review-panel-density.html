  1. 先修了一个真 bug——日志面板的 CSS 把 hidden 属性覆盖掉了，之前是永久显示在右上角，挡住材质表的「备注」列和 Tab 切换按钮。截图前顺手修掉，不然评审看到的是失真状态。
  2. 真正的密度问题不在按钮排，在表格——材质表 11 列、模型块树 12 列，都超出了 460px 的面板宽度，被裁切/滚动掉的恰好是最关键的「备注」「显示」「允许」这些可编辑字段。
  3. 头部 5 个按钮混了三种性质（文件/导出/诊断）却是同一视觉权重，是可以顺手改善的地方，但不是这次最紧急的问题。

01 日志面板永久遮挡

评审开始前发现，不是「要不要折叠」的设计判断，是 CSS 特异性问题——已经修了。

Bug · Critical #logPanel 的 display:flex 覆盖了 hidden 属性 已修复

#logPanel { display: flex } 的选择器特异性比浏览器给 [hidden] 的默认样式高，导致面板从加载那一刻起就常驻显示——盖住材质表右侧的「备注」列，还挡住了材质/贴图/模型块/场景 Tab 切换按钮的点击区域（测试脚本需要 force:true 才能点穿）。改成 #logPanel:not([hidden]) { display: flex } 后恢复正常。

02 表格列数超出面板宽度

这是这次评审里最值得优先处理的问题——不是「好不好看」，是右侧一批可编辑字段实际上不可达。

密度 · 功能性 材质表：11 列挤在 460px 面板里

#、名称、漫反射、金属、粗糙、高光、自发光、混合/面、贴图槽、用于节点、备注——最后一列「备注」是唯一可编辑的文本框，却被挤到视口外，需要横向滚动才能碰到，而且面板本身没有任何「还有内容」的视觉提示。

密度 · 功能性 模型块树：12 列 + 树状缩进，比材质表更挤

刚从平铺表格升级成树状结构（这是好的改动），但列数没跟着精简——名称/属于/顶点三角/通道/材质/移动T/旋转R°/缩放S/显示/允许/备注名称/备注，树状缩进还要再吃掉一部分横向空间。结果是这张表实际能看到的列比材质表更少，「显示」「允许」「备注名称」「备注」这几个真正用来做注释的字段基本都在视口外。

提议：核心列常驻 + 次级信息按行展开——沿用模型块树自己已经建立的 ▸/▾ 展开语言，不是发明新交互。把「顶点/三角、通道、材质、移动T/旋转R°/缩放S」这类只读参考数据收进点击展开的详情行，「名称、属于、显示、允许、备注名称」这些做注释真正要用的字段留在主行常驻可见：

▾ 组 node_3 — ☑ 显示 ☑ 允许 备注名称… ···
▾ L6 node_3 ☑ ☑ 备注名称… ···
展开详情 ▸ 顶点/三角 2378/2332 · 通道 NORMAL POSITION · 材质 ●1 ●2 ●3 ●4 · 移动T 21.761,1.547,20.311 · 旋转R° 0,20,0 · 缩放S 0.004,0.004,0.001

03 头部按钮排缺少分组

优先级低于上面两条，但顺手可以改：5 个按钮是三种不同性质的操作，视觉权重却完全一样。

打磨 · 层级 文件操作 / 导出操作 / 诊断工具，混排成一条线

提议：按性质分三组，用间距而不是新增视觉元素来分隔：

打开 GLB 示例模型
加载
导出注释 JSON 另存为 GLB
导出
日志 ① 诊断

按钮数量还没到需要收进下拉菜单的程度（5 个不算多），先分组、加个组间距就够；等 §3（设置面板）、§10（场景菜单）做出来，「日志」大概率要并进设置面板，这条到时候再一起收。

建议顺序

  • §02 表格拆分优先级最高——现在有实际功能不可达（右侧字段够不到），跟"好不好看"无关，是可用性缺陷。
  • §03 按钮分组顺手做，成本低，跟 §02 不冲突，可以合并到同一轮改动里。
  • 这份评审只出方向，没有动 index.html 的表格/按钮结构——按你说的，讨论定了再排进 TaskList。

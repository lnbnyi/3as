  2. 「透明/面」标着"只读展示"这四个字，在成品界面里读起来像没做完，虽然已经排进 #18，但这种"提前暴露开发状态标签给用户"的做法本身值得记一笔，以后类似情况最好用视觉上的"锁定态"表达而不是直接把内部备注露出来。

01 可见性：选中高亮在全黑材质样品上偏弱

可见性 · 样品相关 细线框 + 黑色几何体 = 容易看漏

选中 PArc864 后，青色包围框出现的位置是对的（截图右侧小方框），但这份样品的材质全部是纯黑 fallback Material，几何体本身跟黑色背景基本融为一体——细线框成了唯一的视觉锚点，稍不注意就会漏看。这不是这次做的功能本身有问题（机制、颜色区分度都没问题），是"这份测试样品材质本来就有问题"和"选中反馈只有细线框一种手段"两件事叠加放大了。

建议：不强制现在改，但可以记一个后续优化方向——选中时除了包围框，给目标网格本身也叠加一层临时的半透明高亮色（用之前材质高亮已经验证过的"叠加 Mesh，只加进 scene 不进 model"这个手法，同一套机制，不是另起一套），这样即使原始材质是纯黑，选中态也不会被材质本身吞掉。

02 实用性：「只读展示」把开发状态露给了用户

实用性 · 措辞 "只读展示"读起来像功能没做完，不像产品决定

这四个字更像是留给自己看的开发备注，不是给用户看的产品文案——用户看到会理解成"这块没做完"而不是"这是当前版本的既定行为"。已经排进 #18 要做成可编辑，等做完这行文字自然就没了；但记一笔通用原则：以后类似"暂时只读"的字段，优先直接不显示这种备注（用正常的只读样式呈现就够了，比如去掉输入框边框、颜色调暗），而不是用文字明说"只读展示"——文字提示应该留给真正需要向用户解释"为什么不能改"的场景（比如"被组锁定，不可单独编辑"这种有信息量的提示）。

03 CSS 统一性：选中高亮色没并入主题变量体系

CSS · 主题一致性 青色/品红是独立硬编码常量，不是 --accent 系的一部分

查了 index.html 源码——主题色本来是一套干净的 :root 变量（--accent 金色系、--bad 红、--ok 绿），这次选中高亮加的两个新颜色是单独定义的硬编码值，没有并入这套体系：

#39d6ff 节点选中框（CSS 里的 tr.node-sel 规则 + JS 里的 NODE_SEL_COLOR 常量，两处独立声明同一个色值）
#ff3fd6 材质高亮叠加色（只在 JS 里，MAT_HL_COLOR 常量）

代码本身写得不差——两个颜色都提成了具名常量、加了注释说明"为什么选这两个颜色"（跟金色场景框、彼此都要区分开），不是随手写的魔法数字。问题是这套颜色活在 CSS 变量体系之外，两个地方（CSS 规则 + JS 常量）各自硬编码同一个值——以后想统一调整主题（比如做个亮色模式，或者品牌色要改）容易漏改其中一处。

现状CSS: #39d6ff（硬编码）
JS: 0x39d6ff（硬编码，两处独立）
建议CSS: --select: #39d6ff;（并入 :root）
JS 读同一个变量值，或者两边都引用一份共享常量

不影响现在能不能用，是维护性问题——排进一个小任务顺手改掉就行，不用单独起一轮大改。
